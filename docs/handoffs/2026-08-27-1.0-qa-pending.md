## Corrections made — do not reintroduce

- **The default-model protection is unconditional**, sole model included. `894aa5b` made it
  conditional on another model existing, reasoning that a lone default would be an undeletable row.
  That was wrong: deleting the *connection* cascades to its models, so nothing was ever stranded, and
  the hint on the disabled buttons is followable with one model anyway. `b6e29a9` removed the special
  case. If you find yourself re-adding an escape hatch, re-read that commit first.
- **`hasUsableModel` and `modelResolves` are deliberately separate** in `resolveOutcome`. "A model
  exists" and "this run will resolve one" are different questions with different remedies, and the
  dialog reports which applies. Merging them reopens the bug `6b01995` fixed.
- **`addDocumentHeaderAction` is not the route to a labelled button**, whatever #16 section 3 says.
  `HeaderActions` renders an `IconButton` with `label` as the accessible name, so the words become a
  tooltip — and at **5.27**, the peer floor and the host's version, the branch is
  `if (action.type === 'icon')` with no else, so an action without it renders **nothing at all**.
  5.52 dropped that check, which is why it looks fine against the devDependency. The working route is
  injection into `editView.right-links`. #16 carries a comment saying so.
- **Never read `isDefault` off i18n's `locales.find()`**, and never read `params.id` as an
  identifier without `documentIdFromRoute`. Both typecheck, run, and answer wrongly in silence;
  both shipped on 27 August and were caught in a browser within seconds. `CONVENTIONS.md` has the
  general rule under "Other plugins' contracts are not what they look like".
- **Node range is 20–22.** The plugin's own `engines` says `>=20`; Strapi 5 hosts cap at 22. The
  README first said 18–22, which was the *host's* range copied from the wrong `package.json`.

## Traps that cost real time this session

`CONVENTIONS.md` has the environment ones. These are new or newly-sharp:

- **"Missing or invalid credentials" is Strapi's session 401, not a credential problem.** It is
  thrown by `@strapi/core/dist/services/auth` and rendered raw above the API key field on the
  provider form, so an expired admin session reads exactly like a rejected Azure key. This misled the
  user for a full round trip. Filed as story 52 on #16, deliberately not fixed. **Reproduce before
  diagnosing:** `curl -X POST http://localhost:1340/ai-bulk-translate/providers` returns it verbatim.
- **Verify what the host runs by integrity hash, not by timestamp.** This was yalc's trap: it
  preserved source mtimes, so a host copy could look older than a build it was byte-identical to.
  `npm run push` now compares `npm pack`'s integrity hash against the host lockfile and fails loudly,
  so it should not bite again. The sharp edge that replaced it: **a bare `npm install` in the host
  will not re-extract a rebuilt tarball of the same version** — it reports "up to date" and keeps
  serving the old build. Always push.
- **Clearing the Vite cache under a *running* host is not enough.** It regenerates, but the server
  must be restarted or the browser is served the old bundle. `npm run push` does the clearing now;
  the order is still push → restart → hard-refresh, every time admin code changes.
- **Minified identifiers prove nothing.** Grepping a built bundle for a component name returns zero
  because it is minified away. Grep for a string literal that survives — a translation key or a
  default message.
- **Strapi gives real buttons to only the first two `position: ['panel']` document actions**
  (`[primary, secondary, ...rest]`); Publish and Save take both, so ours falls into the overflow
  menu. No configuration changes this. Relevant to **story 47** — the route is
  `addDocumentHeaderAction`, which exists in 5.27 and accepts the same dialog.

## Known limits, accepted deliberately

- **The default-model guards are presentation only.** The API still permits all four routes to losing
  the default. Accepted for 1.0 on the grounds that this guards against a slip by a trusted
  administrator, not an adversary. The dialog's `no-model-selected` guard catches the consequence.
  Story 51 is the fix if it ever matters.
- **There is no route through the settings page to zero models or zero connections.** Confirmed with
  the user as intended. Removing the last of either means registering a replacement, promoting it,
  then removing the original. #14 asks QA to *record* this rather than file it as a defect.

## Still open

Both items that stood here when this was first written are now closed: the yalc-vs-tarball decision
(`14e91eb`, #17) and the missing push-restart-verify skill (`6cd3438`). What replaced them:

- **Nothing tracks the release itself.** `package.json` is still `0.1.0` against a milestone called
  1.0; the package has never been published (the registry 404s); there is no CHANGELOG, and no
  `.github/` at all — so no CI, no PR checks, no release workflow. "1.0 ships" currently has no
  definition of done beyond #14, and the gap is already biting: the README's install command cannot
  work until someone publishes. Decide publish-vs-tarball before QA starts, because it changes #14's
  setup step.
- **Six `TS2742` errors from the dts step on every `npm run build`** — `providerRegistry` "cannot be
  named without a reference to `ai/node_modules/@ai-sdk/provider`". Pre-existing, predating the
  tooling work, and the build still exits 0 — but the `.d.ts` shipped to consumers may be degraded.
  Recorded on #17, deliberately not filed as its own issue.
- **`npm install` under npm 11 rewrites `package-lock.json`** with 42 `"peer": true` annotations.
  Pure metadata, no version changes; reverted in `14e91eb` to keep that commit focused. It recurs
  whenever the feedback commands run under the machine default (Node 25) rather than the 22 the host
  needs, so decide which npm owns the lockfile before it churns both ways.

## Unrelated, still outstanding — raised four times now

`../CMS multi-locale` commits live credentials, and it is worse than the previous handoff recorded:

- `config/plugins.ts` holds an OCI private key as `privateKeyBase64`, committed in `fc3e390`. It
  decodes to a real `-----BEGIN PRIVATE KEY`. **Grepping for `BEGIN PRIVATE KEY` finds nothing** —
  that is why it reads as clean — because the value is base64. Decode before concluding.
- `.env.oci` and `.env.oci.prod` are **tracked**: `.gitignore` lists only bare `.env`. Between them
  they commit `ADMIN_JWT_SECRET`, `JWT_SECRET`, `APP_KEYS`, `API_TOKEN_SALT`, `TRANSFER_TOKEN_SALT`
  and `ENCRYPTION_KEY` — that last is the key this plugin encrypts provider credentials with, so
  committing it makes every stored provider key recoverable.

Contained only because that clone still has **no git remote**. It stays contained until someone adds
one or copies the directory. Rotating and scrubbing is a contained job now and a much larger one
after.
